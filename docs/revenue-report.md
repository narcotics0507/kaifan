# 每日营业统计

入口：商家端「数据报表 → 营业额统计」。

1. 选今天、昨天、近7天、本月，或最多366天的日期范围。
2. 上方展示净营业额、收款订单数和日均营业额；趋势可按日、周、月查看。
3. 在「每日汇总」点「查看当天」（手机直接点日期卡片），直接打开当天明细面板。手机全屏，较宽窗口侧边展开，明细在面板内部滚动；关闭后保留汇总页面原位置。面板顶部可切换上一天、下一天或选择范围内日期，查看订单、菜品、收款流水和退菜免单。
4. 点「看账单」在同一面板内查看每道菜的数量、单价、小计、口味、加菜时间及该单操作记录。点「返回当天」恢复当天明细及其滚动位置；点「返回汇总」关闭面板。订单支持搜索桌号或订单号。
5. 「导出完整明细」导出所选范围；「导出当天明细」只导出所选日期。

## 金额与日期口径

- 以北京时间自然日统计。当前现金、微信/支付宝收款码在确认到账时创建支付流水，按该时间归集；跨天开单在收款日入账。
- 收款采用入账金额，现金已扣除找零；待支付、失败、逻辑删除的收款或订单不纳入实收。
- 净营业额 = 当日收款 − 当日整单退款。退款按退款审计时间归集，原收款仍留在原收款日，退款日可以出现负营业额。
- 微信、支付宝、现金和其他净额分别扣除对应方式退款，合计等于净营业额。
- 收款订单数是当日有成功收款流水的去重订单数。同一账单加菜不新增订单；跨天分次收款在各收款日分别计数。零金额免单没有收款流水，不计入收款订单数。
- 日均营业额除以所选自然日天数，包括零营业日期。周使用 ISO 周及 ISO 周年；周/月只汇总筛选范围内日期。
- 结账前退菜、免单、折扣已影响账单应收，不再从收款重复扣除；它们与收款后的整单退款分开列示。
- 当天明细包含当天开单、收款或发生调整的订单。账单应收、当前待收、状态及菜品是查询时状态，不是历史余额快照；当前待收只包含尚待结账的应收差额。
- 菜品明细显示关联订单当前保留的菜品，跨天收款可能关联前一天所点菜品；退掉或换掉的菜见操作记录。菜品小计尚未分摊整单折扣，不等同于当日实收。
- 历史审计日志未记录金额时显示「未记录」并在 Excel 留空，不根据现价推算。

## Excel

工作簿包含七张表：每日汇总（含合计）、订单明细、菜品明细、收款退款流水、退菜免单记录、餐具明细、统计说明。表头冻结，金额显示两位小数，订单/流水号以文本保存。跨日期关联同一订单时，订单明细按统计日期分别列出当日收退款，菜品明细只导出该订单一次。

此功能仅查询现有业务表，不新增或修改订单、流水、库存和桌台状态，营业统计本身不需要数据库迁移；餐具功能通过追加迁移补齐人数及餐具费用字段，历史账单默认0费用，不自动补收。当前真实在线支付未启用；未来接入时需以支付平台成功时间完善对应日期口径。

## 人数与餐具

顾客首次成功下单前确认1至99人的人数，每人默认一套、每套1元。费用在该桌次首个账单中只记一次，顾客加菜与服务员批量加菜都不会重复收取。桌台看板显示当前用餐人数和餐具套数。前台在结账或桌台详情中可调整人数及实际套数（含0套），填写原因，系统保留操作人、时间和增减金额；已收款或桌次结束后不能再修改。

餐具不是菜品，不占菜品库存，不进入后厨做菜小票，不参与菜品折扣、赠送或免单。菜品全部退掉而餐具已使用时，仍保留餐具费待结账。结清后清台，下批客人重新确认人数。历史账单金额保持原样，前台主动补录必须确认数量和原因。

顾客确认下单页使用一行人数步进输入（减、输入、加），人数仍须明确确认；备注按需展开。页底分别展示菜品金额、餐具费用和合计，菜品较多或键盘弹出时仅中间内容滚动。填写口味备注后直接确认，会先完成备注保存再提交订单，并防止重复点击。

## 日结核对

在营业统计点「日结核对」，或在当天明细中切换到同名标签。按北京时间自然日填写微信、支付宝、现金的实际净收款；有其他渠道流水时显示其他渠道。实际净收款为当日实际收款减当日实际退款，现金扣除找零，不填写钱箱余额；退款日允许负数。任一渠道有差额必须填写原因，不能用渠道间相互抵消的总额代替逐项核对。

保存结果包含当时系统账目快照、实际金额、原因、操作人、时间和版本，每次保存追加历史。页面每30秒或回到前台时检查账目变化，保留输入；流水或其他员工的核对记录有变化时须重新加载账目并复核。保存接口也检查版本和账目指纹，拒绝旧页面覆盖。导出已保存记录为带UTF-8标记的CSV，可在Excel打开，包含最近100次的各渠道金额、差额及保存人。更早记录仍在数据库中保留。

核对只记录差异，不修改收款流水、订单、库存或桌台；不替代实际转账及退款，不清台、不停止营业。当前未结账账单单独列出，不计入当天实收。仅具备营业统计权限的后台人员可查看，同时具备收款权限才可保存；顾客不能访问。
